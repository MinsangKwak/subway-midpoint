# 변경·커밋 안내

[폴더·설정](STRUCTURE.md) · [개발 가이드](DEVELOPMENT.md) · [운영](OPERATIONS.md)

**한 커밋에서 해결하는 문제를 분명히 하고, 변경 이유와 확인 결과를 남깁니다.** 이전 커밋 메시지는 다시 쓰지 않고 새 변경을 구분해 기록합니다.

## 시작하기

Node.js 22 이상에서 `npm ci`, `npm run dev`를 실행합니다. nvm 사용자는 `nvm use`로 버전을 맞춥니다. 지도 키 없이도 계산을 검토할 수 있으며 지도 설정은 [운영 가이드](OPERATIONS.md#지도-설정)에 있습니다.

## 변경 절차

1. 최신 dev에서 작업 브랜치를 만듭니다.
2. 관련 코드·스타일·테스트·문서를 함께 수정합니다.
3. `npm run check`를 실행하고, 화면·상태 변경이면 `npm run test:e2e`와 필요한 수동 확인을 수행합니다.
4. 목적별 커밋을 작성하고 dev 대상 PR을 엽니다.
5. 개발 미리보기 검토 후 main 릴리스를 진행합니다.

## 커밋과 PR

| 변경 범위 | 메시지 예시 |
|---|---|
| planner 입력 상태 | `fix(planner): 출발역 변경 시 이전 결과 초기화` |
| 도메인 계산 | `fix(domain): 환승역 출발 시 첫 노선 선택 비용 제거` |
| 데이터 | `chore(data): 13개 노선 원본 갱신과 종점 검증` |
| 브라우저 테스트 | `test(e2e): 주소 복원과 공유 흐름 확인` |
| 폴더·설정 문서 | `docs(structure): 폴더 책임과 공통 설정 안내` |
| 소개·이미지 | `docs(portfolio): 서비스 흐름과 구현 근거 정리` |
| 배포 | `ci(pages): 운영과 개발 빌드 경로 정리` |

예시는 메시지 형식이며 이번 작업에서 해당 코드 변경을 했다는 뜻은 아닙니다. 파일 수보다 변경 목적을 기준으로 나누고, 이미지와 이를 참조하는 문서는 함께 커밋해 중간 상태의 링크가 깨지지 않게 합니다.

PR에는 해결한 문제, 달라진 동작, 실행한 검사, 확인하지 못한 외부 연동을 적습니다. UI 변경이 있으면 실제 화면을 첨부합니다. 단순 문서 수정에 앱 버전을 올리지 않습니다.

## 파일 관리 기준

- 계산은 `domain`, 데이터는 `data`, 화면은 `features`, 연결은 `app`에서 관리합니다.
- 생성된 역 파일을 손으로 수정하기보다 생성 스크립트를 고칩니다.
- 공통 모듈은 특정 기능에 의존하지 않도록 유지합니다.
- 의미 없이 재수출 파일이나 폴더별 설정을 추가하지 않습니다.
- 환경변수 값·원본 캐시·빌드 결과·개인 설정은 커밋하지 않습니다.

문서에 성능·사용자 수·개선율을 추가할 때는 측정 근거를 함께 남깁니다. 자동 검사 통과를 지도 정상 동작이나 접근성 전체 검증으로 표현하지 않습니다.
